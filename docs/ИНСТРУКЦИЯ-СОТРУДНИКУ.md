# K-7 — инструкция сотруднику

## Что входит

Версия для сотрудников содержит пять режимов запуска:

- Codex Desktop;
- Codex CLI;
- OpenCode Desktop;
- OpenCode CLI;
- VS Code с локально обнаруженным расширением `OpenAI.chatgpt`.

В комплекте два приложения:

- `K7-AI-Foundation-Employee-InternalUnsigned.exe` — установка и
  восстановление баз;
- `K7-AI-Launch-Center-Employee-InternalUnsigned.exe` — ежедневный запуск
  клиента через выбранный маршрут.

Оба EXE работают от текущего пользователя, не требуют прав администратора и
не читают логины, OAuth-токены, API-ключи, cookies или историю клиентов.

## Живая инструкция

В правом верхнем углу установщика и центра запуска есть кнопка
**«Инструкция»**. Она открывает встроенный интерактивный дашборд:

1. **Старт** — короткий сценарий для текущего приложения.
2. **Маршруты** — различия Direct, VPN, SingBox HTTP и SingBox HTTPS.
3. **Безопасность** — границы доступа и проверки пакетов.
4. **Восстановление** — `doctor`, отчёты и rollback.

Инструкция берёт редакцию, роль продукта и состояние комплекта из самого EXE.
Для её открытия не выполняются вызовы модели, загрузки или входы в аккаунт.

## Установка

1. Скачайте ZIP целиком и полностью распакуйте его в отдельную папку.
   Не запускайте EXE внутри архива и не переносите один EXE отдельно от
   остальных файлов.
2. Убедитесь, что рядом находятся оба EXE, `bundle-manifest.json` и
   `sing-box-1.13.14-windows-amd64.zip`.
3. Сверьте SHA-256 файлов с `bundle-manifest.json`.
4. Запустите Installer обычным пользователем.
5. Оставьте выбранными Codex и OpenCode и нажмите
   **«Установить выбранное»**.
6. Уже найденная официальная версия внешнего клиента принимается и
   показывается. Если клиента нет, установщик предлагает последнюю
   официальную версию; совпадение с внутренней закреплённой версией не
   требуется.
7. Войдите в каждый сервис только в открывшемся официальном клиенте.
8. После успешной диагностики используйте центр запуска для ежедневной работы.

`InternalUnsigned` может вызвать предупреждение Windows
**«Неизвестный издатель»** или SmartScreen. Это ожидаемо для внутреннего
неподписанного EXE. Предупреждение не заменяет проверку SHA-256 и не означает,
что файл стал публично доверенным.

## Маршруты центра запуска

- **Напрямую** — прямое соединение; унаследованные прокси-переменные очищаются
  только у запускаемого процесса.
- **VPN** — используется уже включённая системная VPN-маршрутизация.
- **SingBox HTTP** — локальный HTTP-шлюз. Для обычных EXE и CLI прокси
  передаётся только запускаемому процессу.
- **SingBox HTTPS** — локальный CONNECT/HTTPS-шлюз с теми же границами.

Для Store Codex переменные отдельного процесса неприменимы. Поэтому Launch
Center временно включает системный прокси текущего пользователя на локальный
порт sing-box. Пока маршрут активен, это может затронуть другие приложения
этого пользователя. Кнопка **«Остановить маршрут»**, штатное завершение и
внутренний аварийный watchdog восстанавливают только те значения, которые
применил Launch Center. Если другая программа успела изменить прокси, её
значения не перезаписываются, а новый AppX-запуск блокируется до проверки.

При первом запуске SingBox центр запуска извлекает среду выполнения из лежащего
рядом архива, проверяет закреплённый SHA-256 и устанавливает её в:

```text
%USERPROFILE%\.llm-foundation\runtimes\sing-box\1.13.14\
```

Повреждённая или неожиданно изменённая среда выполнения не перезаписывается
автоматически: маршрут блокируется с диагностическим кодом.

### Настройка SingBox

1. Выберите **SingBox HTTP** или **SingBox HTTPS**.
2. Заполните подписанные поля **Сервер**, **Порт**, **Логин** и **Пароль**.
   Логин и пароль нужны только для прокси с авторизацией.
3. Нажмите **«Сохранить и проверить»**. Успех означает, что проверочный запрос
   действительно прошёл через локальный sing-box, а временная сессия очищена.
4. Только после успешной проверки выберите клиент и нажмите **«Запустить»**.

Launch Center сам запускает и останавливает `sing-box.exe`. Отдельный скрипт,
ярлык или ручной запуск sing-box пользователю не нужен.

Режим соединения — только транспорт. Этот транспорт не подтверждает право
использования сервиса, не меняет правила провайдера и не должен применяться
для обхода региональных ограничений, блокировки аккаунта или защитных
ограничений провайдера. Каждый сотрудник использует отдельную допустимую учётную запись.

## Ежедневный запуск

1. Откройте центр запуска ИИ.
2. Выберите нужный режим: Codex Desktop, Codex CLI, OpenCode Desktop,
   OpenCode CLI или VS Code + Codex.
3. Выберите Direct, VPN, SingBox HTTP или SingBox HTTPS.
4. Нажмите **«Запустить»**.

Центр запуска разрешает только точную цель, принятую контрактом редакции:

- Store-приложение проверяется по AppX identity и manifest;
- CLI проверяется по локальной записи управляемой команды и SHA-256;
- подмена пути, файла или среды выполнения блокирует запуск;
- Store Codex с SingBox запускается через временную owned-сессию системного
  прокси; уже запущенный Codex этим способом повторно не активируется;
- VS Code запускается только при подтверждённом официальном `Code.exe` и
  локально обнаруженном точном ID расширения `OpenAI.chatgpt`.

## Диагностика и восстановление

Локальные отчёты:

```text
%USERPROFILE%\.llm-foundation\reports\
```

Команды Foundation:

```text
plan
install
doctor
inventory
rollback
```

Восстановление возвращает только управляемую поверхность базы. Оно не удаляет
проекты, историю, авторизацию, cookies, память и данные клиента.

Частые коды маршрута:

- `RUNTIME_BUNDLE_ARCHIVE_MISSING` — ZIP распакован не полностью: архив
  runtime должен лежать рядом с EXE;
- `RUNTIME_ARCHIVE_INTEGRITY_FAILED` — архив повреждён, скачайте ZIP заново;
- `CONFIG_CHECK_FAILED` — проверьте сервер, порт, логин и пароль;
- `LOCAL_PROXY_NOT_READY` — закройте другой VPN/прокси, занявший локальный
  порт, и повторите проверку;
- `ROUTE_PROBE_FAILED` — sing-box запущен, но сквозной запрос не прошёл;
- `SYSTEM_PROXY_CHANGED_EXTERNALLY` — другое приложение изменило системный
  прокси; Launch Center не стал перезаписывать это изменение.

## Сборка версии для сотрудников

Финальная внутренняя сборка требует принятые каталоги пакетов и точный архив
среды выполнения:

```powershell
pwsh -NoProfile -File .\tools\build-edition.ps1 `
  -OutputRoot .\dist\employee-internal `
  -Edition Employee `
  -DistributionMode InternalUnsigned `
  -PackageRoot <accepted-codex-opencode-packages> `
  -FoundationPackageRoot <accepted-foundation-package> `
  -ClientSourcesLock .\client-sources.lock.json `
  -RuntimeSourcesLock .\runtime-sources.lock.json `
  -RuntimeArchive .\.work\runtime-cache\sing-box-1.13.14-windows-amd64.zip
```

Результат содержит два EXE, архив среды выполнения и общий
`bundle-manifest.json`. Сборщик проверяет SHA-256 runtime до копирования и
после него.

## Канонический релизный конвейер

```powershell
py -3.12 .\tools\hub_canary.py `
  --execute-approved-hub-canary `
  --bundle .\dist\employee-internal `
  --output .\dist\employee-hub-canary.json

py -3.12 .\tools\installer_release.py `
  --bundle .\dist\employee-internal `
  --hub-canary .\dist\employee-hub-canary.json `
  --output .\dist\employee-draft-0.3.0
```

Контрольный прогон работает только во временных изолированных профилях и не
вызывает модели. Пилот на чистом ПК обязан проверить теми же байтами
установщик, центр запуска, Codex/OpenCode, интерактивную инструкцию и все четыре маршрута.
Перечень подтверждений выводит:

```powershell
py -3.12 .\tools\pilot_evidence.py --help
```

После PASS пилота формируется стабильный набор без пересборки и публикуется
неизменяемый релиз `employee-v0.3.0`. Проверка после публикации:

```powershell
py -3.12 .\tools\installer_release_verifier.py `
  --stable-root .\dist\employee-stable-0.3.0 `
  --output .\dist\employee-v0.3.0-release-verification.json
```

Текущий статус до повторной проверки: `CLEAN_PC_PILOT=PENDING`. Prerelease
для рабочего ПК не является стабильным `employee-v0.3.0`.

## Перед выдачей сотруднику

- Приёмка пакетов Codex и OpenCode — PASS.
- Приёмка пакета Foundation — PASS.
- Архив среды выполнения совпадает с `runtime-sources.lock.json`.
- Полный набор тестов Windows — PASS.
- Четыре финальных экрана проверены визуально.
- Пилот на чистом Windows x64 пройден теми же байтами.
- Удалённый релиз неизменяем, а каждый файл повторно проверен после публикации.

`Preview` не является employee-релизом. `InternalUnsigned` разрешён только для
контролируемого внутреннего распространения после всех перечисленных гейтов.
