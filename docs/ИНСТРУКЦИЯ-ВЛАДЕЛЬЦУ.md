# K-7 — инструкция владельцу

## Контур владельца

Версия владельца содержит:

- Codex Desktop и Codex CLI;
- Claude Code;
- OpenCode CLI.

Контракт редакции жёсткий:

```text
owner_controlled=true
distribution_allowed=false
перераспространение запрещено
```

В комплекте единое приложение и ярлык:

- `K7-AI-Foundation-Owner-InternalUnsigned.exe` — установка и центр запуска;
- `K7-AI-Launch-Center-Owner-InternalUnsigned.cmd` — ярлык центра запуска
  (открывает тот же EXE).

Эта сборка предназначена только владельцу. Её нельзя передавать сотрудникам,
публиковать как версию для сотрудников или использовать как доказательство допуска
провайдера.

## Интерактивная инструкция

Кнопка **«Инструкция»** в установщике и центре запуска открывает встроенную
hi-tech консоль с четырьмя живыми разделами:

1. `01 / СТАРТ`
2. `02 / МАРШРУТЫ`
3. `03 / БЕЗОПАСНОСТЬ`
4. `04 / ВОССТАНОВЛЕНИЕ`

Консоль показывает точную версию, роль программы, набор целей и наличие
манифеста комплекта. Она не вызывает модели, не выполняет авторизацию и не
отправляет телеметрию.

## Состояния Claude

Наличие проверенного локального пакета и готовность провайдера — независимые
состояния:

- `TECHNICAL_READY` — официальный закреплённый Claude Code и его пакет прошли
  технические проверки;
- `PROVIDER_LIVE` — отдельный допустимый интерактивный вход завершён либо
  возвращён `BLOCKED_PROVIDER_ELIGIBILITY`;
- `INTERNAL_UNSIGNED_RELEASE` — технический внутренний комплект собран, но не
  является stable/public.

Claude Code входит в Owner, Employee и Simple. Центр запуска может по явному
действию пользователя открыть официальный клиент независимо от provider-гейта,
не объявляя доступность аккаунта подтверждённой.

Каждый вход выполняется владельцем интерактивно в официальном клиенте.
Обход региона, блокировки аккаунта и защитных ограничений не используется.
VPN или прокси остаются транспортом, а не способом изменить допустимость аккаунта.

Перед новым evidence сверяются актуальные первоисточники:

- [Supported countries & regions](https://www.anthropic.com/supported-countries);
- [Consumer Terms of Service](https://www.anthropic.com/legal/consumer-terms).

Обезличенное свидетельство провайдера создаётся локально:

```powershell
pwsh -NoProfile -File .\tools\new-provider-eligibility-evidence.ps1 `
  -OutputPath .\provider-eligibility-evidence.json `
  -ConfirmEmployeeLocationEligibility `
  -ConfirmOrganizationEligibility `
  -ConfirmIndividualAccounts `
  -ConfirmNoRegionOrBanBypass `
  -ConfirmNoUnattendedConsumerAutomation
```

`ProviderEligibilityEvidence` действует не более 7 суток. Он не содержит ФИО,
IP, электронной почты, страну или идентификатор аккаунта. Автоматизированный
потребительский доступ без участия человека не подразумевается.

## Установка

1. Поместите рядом установщик владельца, центр запуска владельца и
   `sing-box-1.13.14-windows-amd64.zip`.
2. Сверьте SHA-256 с `bundle-manifest.json`.
3. Запустите Installer обычным пользователем.
4. Проверьте отдельные состояния Codex, Claude и OpenCode.
5. Выберите маршрут и установите нужные цели.
6. Выполните вход только внутри официального клиента.
7. Проверьте `doctor` и сохраните локальный отчёт.

`InternalUnsigned` может показать «Неизвестный издатель» или SmartScreen.
Версия владельца остаётся внутренним неподписанным кандидатом и не выдаётся за
публично подписанный продукт.

## Маршрутная матрица

- **Напрямую** — прямой запуск без унаследованного прокси.
- **VPN** — системная VPN-маршрутизация.
- **SingBox HTTP** — локальный HTTP-шлюз только для процесса.
- **SingBox HTTPS** — локальный HTTPS/CONNECT-шлюз только для процесса.

При первом запуске SingBox среда выполнения устанавливается из локального
архива с проверкой хеша в:

```text
%USERPROFILE%\.llm-foundation\runtimes\sing-box\1.13.14\
```

Повреждённая среда выполнения блокирует запуск и не заменяется молча.
AppX-клиент нельзя безопасно активировать с локальным прокси-окружением
процесса; для него разрешены прямое подключение и системный VPN.

## Точные цели Launch Center

- Store-клиент проверяется по семейству пакета, издателю, архитектуре,
  типу подписи, идентификатору приложения, точке входа и исполняемому файлу.
- Управляемый CLI проверяется по `current.json`, ожидаемому относительному пути и
  SHA-256 исполняемого файла.
- Перед каждым запуском целевая целостность проверяется повторно.
- Центр запуска управляет только запущенным им процессом и своим локальным
  SingBox-сеансом.

## Восстановление

Отчёты:

```text
%USERPROFILE%\.llm-foundation\reports\
```

Рабочие команды:

```text
plan
install
doctor
inventory
rollback
```

Восстановление не удаляет проекты, историю, авторизацию, память, cookies или
пользовательские данные вне управляемой поверхности.

## Сборка версии владельца

```powershell
pwsh -NoProfile -File .\tools\build-edition.ps1 `
  -OutputRoot .\dist\owner-internal `
  -Edition Owner `
  -DistributionMode InternalUnsigned `
  -PackageRoot <accepted-owner-packages> `
  -FoundationPackageRoot <accepted-foundation-package> `
  -ClientSourcesLock .\client-sources.lock.json `
  -RuntimeSourcesLock .\runtime-sources.lock.json `
  -RuntimeArchive .\.work\runtime-cache\sing-box-1.13.14-windows-amd64.zip
```

Свидетельство провайдера передаётся отдельным параметром только когда оно реально
есть и актуально:

```text
-ProviderEligibilityEvidence <provider-eligibility-evidence.json>
```

Без него `PROVIDER_LIVE` остаётся `BLOCKED_PROVIDER_ELIGIBILITY`; техническая
готовность официального клиента не подменяет допустимый live-доступ.

## Перед использованием

- Приёмка пакетов Codex/OpenCode — PASS.
- Приёмка пакета Claude отделена от готовности провайдера.
- Приёмка пакета Foundation — PASS.
- Архив среды выполнения совпадает с закреплённым lock-файлом.
- Полный набор тестов и визуальная проверка четырёх интерфейсов — PASS.
- `distribution_allowed=false` сохранён в Owner manifest.

Кандидат владельца можно использовать локально под его контролем.
Распространение сотрудникам и публичная публикация версии владельца запрещены.
